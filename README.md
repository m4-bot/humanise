# Dengue Risk Spotter (DengueGuard AI)

> **Practice project, not a clinically validated medical device.** All supplied sample cases are synthetic. A predicted "High" or "Low" value must never replace medical assessment or be used for patient triage.

## 1. Title and description

Dengue Risk Spotter is a small Bangladesh-focused learning application. A user enters patient and local-environment values, a Random Forest model returns a **practice-only** risk label, and a React/Leaflet map visualizes example case locations.

**Practice goal:** CSV data -> MySQL storage -> Random Forest training -> FastAPI JSON endpoints -> React/Leaflet interface.

**Repository:** https://github.com/m4-bot/humanise

**Project status:** In progress. Before describing the app as live or ready for judging, verify the actual backend, frontend and database integration using the checklist below.

## 5. Setup and run (Windows PowerShell)

### Prerequisites

Install Python, Node.js + npm, Git, and MySQL if testing the database integration. Run the commands from the cloned repository's root (`humanise`) unless otherwise stated.

### Backend: prepare and train

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\.venv\Scripts\python.exe backend\train.py
```

The training command needs `data/dengue_sample.csv` with the expected column names. If successful, it should create `backend/models/random_forest.joblib` and print a test accuracy. With approximately 30 synthetic rows, this accuracy is **not evidence of medical validity**.

### Backend: start API (Terminal 1)

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload
```

Open **http://127.0.0.1:8000/docs** to test API routes. This command works only after `backend/main.py` has been implemented correctly.

### Database: configure if supported

1. Create a local `.env` file using the keys in `.env.example` and replace placeholder values **locally**. Never commit `.env`.
2. Open `database/schema.sql` in MySQL Workbench or another MySQL client and execute it against your local MySQL server.
3. Import the synthetic CSV using the team's loading script, if implemented, and verify the `patient_cases` table has records.

**Note:** Creating `database/schema.sql` in GitHub does not automatically create or populate MySQL. An early `/cases` implementation might read directly from CSV; document the actual behavior after testing.

### Frontend: start website (Terminal 2)

After the React/Vite frontend exists and `frontend/package.json` is present:

```powershell
cd frontend
npm install
npm run dev
```

Open the local URL printed by Vite (often **http://localhost:5173**). Leave both terminals running. If the frontend cannot reach FastAPI, verify the API base URL, backend server, and CORS settings.

## 6. API contract

**GET /**: simple health response, for example `{"status":"ok"}`.

**POST /predict**: JSON request example:

```json
{
  "district": "Dhaka",
  "area_type": "urban",
  "age": 24,
  "fever_days": 5,
  "temperature_c": 38.9,
  "platelet_count": 62000,
  "wbc_count": 2800,
  "rainfall_mm": 310,
  "lat": 23.7806,
  "lng": 90.4193
}
```

Expected response shape (the numbers are **illustrative**, not a guaranteed model prediction):

```json
{
  "status": "ok",
  "model_name": "random_forest",
  "high_risk": 1,
  "risk_probability": 0.87,
  "risk_label": "High"
}
```

**GET /cases**: `{"status":"ok","cases":[{"id":1,"district":"Dhaka","lat":23.7806,"lng":90.4193,"high_risk":1}]}`.

Error response shape: `{"status":"error","message":"age must be a number"}`.

Keep JSON key names consistent. `high_risk` is `0` or `1`; `risk_label` is `"Low"` or `"High"`.
